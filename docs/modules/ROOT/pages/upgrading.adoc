:description: What behaves differently in 26.12.1 for a program written against 26.11.1 or one of its post releases, and what is new in the two Python packages.

Read this page before you move a program from 26.11.1, or from one of its post releases, to 26.12.1. It covers both packages, `{native-pkg-name}` and `{jvm-pkg-name}`. The changes of the engine itself are listed with the https://github.com/ArcadeData/arcadedb/releases[releases of ArcadeDB].

[[changed-behaviour]]
== Changed behaviour

=== A write outside a transaction commits on its own

Before, such a write raised `ArcadeDBError` with "Transaction not begun" in the message. Now the statement runs in a transaction of its own and commits when it ends. This holds for every database that the packages hand out, the databases of an embedded server included.

* Code that uses `with db.transaction():`, or `db.begin()` with `db.commit()`, behaves as before.
* Code that relied on the error, for example to catch a write that is not in a transaction, must call `db.set_auto_transaction(False)`. The setting is not stored, so call it after every open. See xref:how-to/transactions.adoc#strict-mode[Strict mode].
* A loop of single writes pays one commit for each of them. Put many writes in one transaction: see xref:how-to/transactions.adoc#commit-cost[What a commit costs].

=== The text of an error starts with its code and a hint

`str(e)` of a failure that the packages recognize is `[code] hint`, followed by the text that the error had before.

* Code that compares the whole text, or its beginning with `startswith`, no longer matches. Test `e.code` or the class of the error, or search the text with `in`. `e.to_dict()["message"]` is the text without the code and the hint.
* A common cause raises a subclass of `ArcadeDBError`, such as `DuplicateKeyError`. `except ArcadeDBError` still catches it, but `type(e) is ArcadeDBError` is false.
* A failure with the code `unknown` keeps its class and its text.

See xref:how-to/errors.adoc[Errors: codes, hints and classes].

=== NumPy is imported when it is first needed

`import arcadedb` no longer imports NumPy itself (`{jvm-pkg-name}` can still import it at that point through JPype). A NumPy that is installed but cannot be imported now raises at the first call that needs it. Before, the packages acted as if NumPy were not installed.

=== `{native-pkg-name}` writes text outside ASCII as it is in `Result.to_json()`

Before, `{native-pkg-name}` wrote every character outside ASCII as a `\u` escape. Now it writes the character itself, as `{jvm-pkg-name}` does, and keeps an escape only for control characters, U+2028 and U+2029. The parsed values are the same. Only the text, and so its length, its bytes and a hash of it, differs from what `{native-pkg-name}` returned before.

=== `{native-pkg-name}` stores a whole number from `insert_many` as `{jvm-pkg-name}` does

Before, `{native-pkg-name}` stored every whole number that `insert_many` wrote as a `Long`. Now it stores an `Integer` when the number fits 32 bits, also inside a list or a dict, and a `Long` beyond that, as `{jvm-pkg-name}` does. A property that the type declares keeps its declared type, the values that Python reads back are the same, and records that are already stored do not change. Code that asks for the stored type, for example with the SQL method `type()`, can see `INTEGER` where it saw `LONG`. See xref:how-to/bulk-loads.adoc[Bulk loads and commit size].

=== A conflict after a block committed part of its work raises `PartialCommitError`

Before, `db.run_in_transaction(fn)` and `with db.transaction():` raised `ConflictError` when a block lost a conflict after a `BATCH n` boundary, or a `commit()` inside it, had stored part of its work. The hint said to run the transaction again, which applied that part a second time. Now they raise `PartialCommitError` with the code `partial_commit`, which is not a `ConflictError`.

* Code that catches `ConflictError` to retry no longer catches this case. Catch `PartialCommitError`, check what is stored, and decide what to run again.
* A block that committed nothing behaves as before.

See xref:how-to/errors.adoc#partial-commit[A block that already committed part of its work].

=== Engine 26.12.1

The engine that the 26.12.1 packages carry changes some behaviour that the other pages describe:

* A vector index that `CREATE INDEX ... LSM_VECTOR` makes without `addHierarchy` has the HNSW hierarchy layers; on 26.11.1 and earlier it was a flat graph. `create_vector_index` already asked for the layers. See xref:how-to/vectors.adoc[Vectors].
* A new `LSM_VECTOR` index with more than 16,384 dimensions is refused, and so is the first vector of that length in an index that takes its dimensions from it. To create a wider index, first run `+ALTER DATABASE `arcadedb.vectorIndex.maxDimensions` 20000+`, with the number that your vectors need. An index that is already stored keeps working. See xref:how-to/vectors.adoc#dimension-limit[The dimension limit].
* `EXPORT DATABASE` refuses a setting that it does not know and some values that it accepted before: see xref:how-to/import-export.adoc[Importing and exporting data].

Keep a backup of the database directory before you upgrade. With the engine change https://github.com/ArcadeData/arcadedb/pull/12239[ArcadeData/arcadedb#12239], a read-write open labels the database, and 26.11.1 then refuses to open it. The way to prevent the label is on xref:installation.adoc#older-wheel[Open a database with an older wheel].

== New

* `open_or_create_database(path)` opens the database when it exists and creates it when it does not: see xref:how-to/databases-and-queries.adoc#open-or-create[Open or create].
* Every error has `code`, `hint`, `cause` and `to_dict()`: see xref:how-to/errors.adoc[Errors: codes, hints and classes].
* Both packages ship type hints on every public class and function, and a `py.typed` marker (PEP 561). A type checker now reads them, so it can report problems in your code that it did not report before.
* The `FACETS` clause and the `COLUMNAR` index, which need engine 26.12.1: see xref:how-to/facets.adoc[Faceted queries].
