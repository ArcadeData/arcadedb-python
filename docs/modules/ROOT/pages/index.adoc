= ArcadeDB Python
:description: Run the ArcadeDB engine inside your Python process: install, first steps and how-to guides for the arcadedb (native) and arcadedb-jvm (JVM) packages.

// Sources: bindings docs index.md, api-access-methods.md and getting-started/installation.md,
// and the PyPI descriptions of arcadedb and arcadedb-jvm.

These packages run the ArcadeDB engine inside your Python process, with no network hop and no server to start. Two packages exist, and both use the import name `{import-name}`:

[cols="1,3,3"]
|===
| Package | Engine | Pick it for

| `{native-pkg-name}` (the default)
| Native: the engine compiled by GraalVM Community Edition, loaded with `ctypes`. No JVM, no JPype.
| Scripts, notebooks, tests, CLIs, serverless functions and agents.

| `{jvm-pkg-name}`
| JVM: the Java engine in your process through https://jpype.readthedocs.io/[JPype], with a bundled Java 25 runtime.
| Heavy, long-running loads, and the Java-object APIs.
|===

Not sure which one? Read xref:which-package.adoc[Which package?]. Install one of them, not both.

ArcadeDB is a multi-model database: graph, document, key/value, vector and time series data live in one database, and you query it with SQL or openCypher. The bindings expose the two calls you need for that, `db.command(...)` and `db.query(...)`.

[source,python,subs="attributes+"]
----
{import-stmt}

with arcadedb.create_database("./mydb") as db:
    db.command("sql", "CREATE DOCUMENT TYPE Person")
    with db.transaction():
        db.command("sql", "INSERT INTO Person SET name = ?, age = ?", "Alice", 30)
    for record in db.query("sql", "SELECT FROM Person WHERE age > 25"):
        print(record.get("name"))
----

[source,text]
----
Alice
----

This page is the map. xref:installation.adoc[Installation] and xref:quickstart.adoc[Quickstart] get you to a working database, and the xref:how-to/databases-and-queries.adoc[how-to guides] go deeper.

[[embedded-vs-http]]
== Embedded bindings or the HTTP driver

ArcadeDB reaches Python in two ways. Pick by where the engine should run.

[cols="1,2,2"]
|===
| | Embedded bindings (this component) | HTTP driver

| Where the engine runs
| In your Python process
| In a separate ArcadeDB server

| Who can reach the data
| One process at a time: the database directory is locked while it is open
| Any number of clients, local or remote

| Network round trip
| None
| One per call

| Setup
| `pip install {native-pkg-name}` or `pip install {jvm-pkg-name}`
| A running server (the official Docker image `arcadedata/arcadedb`), plus `pip install arcadedb-driver`
|===

Choose the embedded bindings for a single script, a notebook, or an application with one Python process that owns its data. Choose the xref:arcadedb::how-to/connectivity/drivers/python-http.adoc[HTTP driver] when more than one process, another language, or a remote machine must reach the same database, or when the server must outlive your Python process.

The two meet in one case. The bindings bundle an optional HTTP server. It is off until you call `create_server()`. The process that owns the database keeps direct access, and other processes connect over HTTP. That server lives and dies with your Python process. For a database that must outlive any one client, or for HA, replication and TLS, run the regular xref:arcadedb::index.adoc[ArcadeDB server] instead.

[[jvm-vs-native]]
== Native build or JVM build

Both packages give you the same engine and the same API. The table in xref:which-package.adoc[Which package?] lists what differs: start-up time, memory, platforms, and the APIs that exist only on the JVM build (`get_java_database`, `jvm_kwargs`, `start_jvm`). The pages in this component apply to both packages. Parts that apply to one only say so.

Check which one you have with `python -c "import arcadedb; print(arcadedb.__backend__)"`. It prints `native` or `jvm`.

== Requirements

* Python 3.11 to 3.14, and 3.15 for `{native-pkg-name}`. The wheels' CI runs all four versions on every supported platform for `main`, the nightly run and each release. A pull request runs a smaller selection (xref:development/ci.adoc[Continuous integration]).
* Linux (x86_64 and ARM64, glibc: no Alpine), macOS on Apple Silicon (no Intel Mac), or Windows (x86_64). The Windows wheel of the native build is the newest. The glibc floors and the other platforms that are not built are in xref:installation.adoc#requirements[Requirements].
* No Java installation, for either package.
